# 開發部署流程

## 三個環境

| 環境 | 分支 | URL | 用途 |
|---|---|---|---|
| **本機 Docker** | dev | http://localhost:8000 | 開發實驗，隨便改 |
| **GitHub dev** | dev | 不部署 | 暫存 code |
| **Zeabur 正式** | main | https://shuangyun-agent-platform.zeabur.app | 穩定上線 |

---

## 日常開發流程

### 1. 在 dev 分支開發

```powershell
# 確認在 dev 分支
git checkout dev

# 寫 code...

# 本機 Docker 測試
docker compose up -d --build
# 打開 http://localhost:8000 測試

# 確認沒問題，commit
git add <files>
git commit -m "feat: 描述"
git push origin dev
```

### 2. 確認要上線時，merge 到 main

```powershell
# 切到 main
git checkout main

# 合併 dev
git merge dev

# push → Zeabur 自動部署
git push origin main

# 切回 dev 繼續開發
git checkout dev
```

### 3. 如果上線後發現問題，快速 rollback

```powershell
# 在 Zeabur dashboard → Deployments → 點之前的版本 → Redeploy
# 或在本機：
git checkout main
git revert HEAD
git push origin main
git checkout dev
```

### 啟動

```powershell
docker compose up -d --build
```

### 查看 log

```powershell
docker compose logs -f shuangyun-agent
```

### 重建（改了 code 後）

```powershell

```

### 停止

```powershell

```

### 進入容器（偵錯用）

```powershell

```

## Docker vs Zeabur 環境差異

| 設定 | 本機 Docker | Zeabur |
|---|---|---|
| .env | 讀本地 `.env` | Zeabur dashboard 設定 |
| Skill 來源 | `SKILL_SOURCE=local` + volume mount | `SKILL_SOURCE=gdrive` + Drive API |
| 資料庫 | `./data/shuangyun-agent.db`（本機） | Zeabur persistent volume |
| API Key | 本地 .env 的 key | Zeabur env vars |

### 避免環境差異的方法

1. **Docker 用跟 Zeabur 一樣的 Node 版本**（Dockerfile 已固定 Node 24）
2. **不直接用 `npm start` 開發**，永遠用 `docker compose up -d --build`
3. **環境變數差異只有 Skill 來源和 API Key**，其他都一樣
4. **.env 不進 git**（已在 .gitignore），不會互相干擾

## 完整流程圖

```
本機 Docker（dev 分支）
    ↓ git push origin dev
GitHub dev 分支（不部署）
    ↓ git checkout main && git merge dev && git push
GitHub main 分支
    ↓ 自動觸發
Zeabur 部署（正式環境）
```

**關鍵原則：dev 分支盡情改，main 分支只放穩定版。**
